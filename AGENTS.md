# AGENTS.md

Guidance for coding agents working in this repository.

## Project Overview

**suave_rebetmc** is a managing system for the SUAVE AUV pipeline-inspection mission. It has Xtext/FeatureIDE and older TypeDB KB paths (via `typedb_tactics`) and uses `adapt_x`/AAL for adaptation execution. Check the selected launch/config path before assuming a TypeDB server is required. The managed system is SUAVE; this package is the *managing subsystem* that drives it through standard ROS 2 interfaces.

## Build And Test Commands

Run inside the container (`suave_rebetmc`). Workspace: `/home/ubuntu-user/suave_ws`.

```bash
docker exec suave_rebetmc bash -lc 'cd /home/ubuntu-user/suave_ws && source /opt/ros/humble/setup.bash && source install/setup.bash && <command>'

colcon build --symlink-install
colcon build --symlink-install --packages-select suave_rebetmc
colcon test --packages-select suave_rebetmc --event-handlers console_direct+ --ctest-args -E '^test_suave_tactics_kb$'
colcon test-result --verbose
python3 -m pytest -q src/suave_rebetmc/test
ros2 pkg executables suave_rebetmc
```

The TypeDB-backed KB pytest is registered as `test_suave_tactics_kb`; its
`typedb` label assignment is currently commented out. Exclude it by name unless
a compatible TypeDB server is running on `localhost:1729`.
From the host workspace, `python3 scripts/focused_test.py --package suave_rebetmc`
handles this exclusion (override with `--with-typedb`) and checks test exit codes.
The wrapper does not build; rebuild interfaces/C++/installed assets first.

Focused adapt_x tests should be run in the running `suave_rebetmc` container when they need ROS/JVM dependencies:

```bash
python3 scripts/focused_test.py --test src/adapt_x/adapt_x/test/test_aal_failures.py
```

**Mandatory lint gate:** before marking work complete, run `test_flake8`, `test_pep257`, and `test_copyright` and ensure all pass.

For local verification in this workspace, prefer the system CMake and writable ccache dirs if the sandboxed environment selects `/home/gus/.local/bin/cmake` or ccache tries to write under read-only paths:

```bash
export PATH=/usr/bin:$PATH
export CCACHE_TEMPDIR=/tmp/ccache-tmp
export CCACHE_DIR=/tmp/ccache
```

## Generated Code Rules

- `src-gen/` is generated by rebetmc_eclipse_projs Xtext/MWE2 workflows and by `ros2model`. Do not hand-edit.
- After editing `.context`, `.var`, `.resolution`, or `.tactics` files, regenerate `src-gen/` from the Eclipse IDE with the rebetmc plugins installed.
- `models/typedb/suave_tactics.tql` is a symlink to `src-gen/suave_tactics.tql` — never edit it directly.
- Runtime model paths in `config/adaptation_engine_config.yaml` should resolve under `<suave_rebetmc_models_dir>`:
  - `.ros` files: `models/interfaces/`
  - `.ros2` files: `models/ros/`
  - `.rossystem` files: `models/system/`
  - `.context`, `.var`, `.resolution`, `.tactics`, `.reqs`: `models/tactical_retreat/`
- The launch file replaces `<suave_rebetmc_models_dir>` with `share/suave_rebetmc/models`.
- CMake, not `setup.py`, owns package installation. Keep `config`, `launch`, `models`, and `bts` installed under `share/suave_rebetmc`.

## Behavior Tree Runner

- `suave_rebetmc_bt` loads `share/suave_rebetmc/bts/suave.xml`.
- Reuse mission action/condition nodes from `suave_bt`; do not duplicate those BT node implementations in this package.
- Do not add `ChangeMode` or `previous_modes` blackboard wiring unless a future tree actually uses them.
- `EnsureConfiguration` comes from `aal_bt`. Because `aal_bt` currently exports a CMake library path that may not resolve with `find_package(aal_bt)`, `suave_rebetmc_bt` loads the installed BT plugin at runtime from `share/aal_bt/bt_plugins/libaal_bt_nodes.so`. Keep `aal_bt` as a package dependency in `package.xml`.

## adapt_x / JPype Runtime Notes

- JPype Java package imports require `import jpype.imports` before statements like `from org.ros2.rcljava.rebet_java import RosToolingSupport`.
- Add `share/adapt_x/jars/rem/*` to the JPype classpath before starting/importing Java classes. The `rebet_java.jar` contains `org/ros2/rcljava/rebet_java/RosToolingSupport.class`.
- Loading FeatureIDE/Rhea-backed models needs EMF package initialization, not just JAR presence:
  - `AdvancedConstraintsFMmetamodelPackage.eINSTANCE.eClass()`
  - `BasicFMmetamodelPackage.eINSTANCE.eClass()`
- `Resource` from `org.eclipse.emf.ecore.resource` is a Java interface; do not instantiate it. For `TQLGenerator.rossystemfromContextModel(ContextModel, Resource)`, pass an existing EMF resource such as `self.tacticsModelResource`.
- If `requirements_path` is empty, `adapt_x` should not call `requirementsResources.get(0)`. A valid `.reqs` file can be minimal, e.g. `REQ1, Safety: "Placeholder requirement.", true`, but placeholder requirements should be replaced with real SUAVE requirements.
- Do not assume APIs from other branches such as `adapt_x.tql_output` exist.
  Check the active source before using generated-query persistence helpers;
  prefer isolated tests instead of constructing the full `AdaptationEngine`.

## ROS Managing Subsystem Interface

Must interact with:
- `/diagnostics` (`diagnostic_msgs/DiagnosticArray`)
- `/task/request`, `/task/cancel` (`suave_msgs/srv/Task`)
- `ChangeMode` services: `/f_maintain_motion/change_mode`, `/f_generate_search_path/change_mode`, `/f_follow_pipeline/change_mode`

## Coding Style

- Hybrid package: `ament_cmake` + `ament_cmake_python`; do not reintroduce `setup.py`.
- Python: `rclpy.node.Node`, `snake_case`, `PascalCase` classes.
- C++: C++17, ROS 2 style, `ament_target_dependencies`.
- Apache-2.0 header with `Copyright 2026 KAS-lab` on new C++ and Python files.
- Single-line docstrings where appropriate; keep flake8/pep257/copyright clean.
